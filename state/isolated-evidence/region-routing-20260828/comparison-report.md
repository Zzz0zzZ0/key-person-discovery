# SearXNG 地区引擎隔离 A/B（2026-08-28）

## 边界

- 使用 3 个既有 CRM 输入快照，不创建 SQLite job 或 batch，不写 CRM，不发信。
- AnySearch 和海关 AnySearch 预算均设为 0；两组只比较 SearXNG 引擎组。
- 基线：Bing、DuckDuckGo、Google CSE、Qwant。
- 地区组：韩国在基线上追加 Naver，俄罗斯在基线上追加 Yandex。
- 两组均开启既有 broad discovery，以保证每条查询都执行 SearXNG；每家公司 `max_urls=15`。

## 归属与质量审计

SOEZ 地区组新增的 6 个联系方式均来自目标公司官网，没有发现网页设计商、认证机构、法律/隐私服务商、代理商或其他公司的联系方式。3 个 CRM 重复项被现有规则移除。

但 4 个候选不能直接当作 4 名 Key Person：

- `Главный инженер`、`Отдел снабжения`、`Отдел по работе с клиентами` 是职位或部门，不是具名个人；其电话的真实部门归属有证据，但应作为公司/部门渠道展示。
- `Tatyana Pleshakova` 是具名员工候选，但她的 evidence 数组混入了总工程师和采购部门电话的证据；联系方式没有实际绑定到她，仍属于证据污染，需要人工复核。

所以对“外部公司联系方式误归属”计 0，对“候选结构或证据误归属”计 4。本次正向增量主要是 6 个可人工开发的公司/部门联系方式，不是 4 名已验证 Key Person。

## 结论

地区路由对俄罗斯公司有明显召回增量，对两个韩国样本没有联系人增量。保留代码和隔离结果，但不启动批量生产：下一步应先阻止职位/部门进入具名候选，并把部门电话保留为真实归属的公共渠道；修复后用同一 3 家公司复测，再决定是否批量启用。公司评分、产品适配和验证状态均未参与引擎选择、搜索预算或保留数量。
