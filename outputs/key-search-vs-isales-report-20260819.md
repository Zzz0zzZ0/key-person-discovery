# Key Search 与 iSales 业务效果对比报告

报告日期：2026年8月19日

## 一、业务结论

本报告对 Key Search 与 iSales 的联系人挖掘效果进行客观对比，不讨论系统替换或工具采购决策。

本次对比体现出的功能特点是：

- Key Search 同时提供公司判断、官网负责人、公共联系方式和当前任职证据。
- iSales 提供更大规模的员工名单、部门岗位和个人邮箱候选。
- Key Search 会区分已确认人员、待确认人员和公司公共联系方式。
- iSales 的输出更偏向候选数据集合，仍需进一步核对任职和联系方式状态。

总体来看，Key Search 更侧重证据可信度和当前任职确认；iSales 更侧重人员数量、部门覆盖和邮箱候选规模。

## 二、测试范围

本次选择三家不同规模和类型的工业企业进行同公司对照：

- Grinding Techniques
- Samancor Chrome
- Pace Industries

对比重点是人员数量、目标岗位覆盖、联系方式、当前任职可信度以及错误数据风险。

## 三、总体结果

| 业务指标 | iSales | 当前 Key Search | 业务判断 |
|---|---:|---:|---|
| 去重后人员 | 119人 | 35人 | Key Search 人员数量约为 iSales 的29% |
| 公司公共邮箱和电话 | 18条 | 16条 | 两者数量接近 |
| 当前任职已确认人员 | 未统一区分 | 25人 | Key Search 的可信度更高 |
| 需要人工确认人员 | 未统一区分 | 10人 | Key Search 会明确提示不确定性 |
| 个人邮箱候选值 | 359个 | 少量直接证据值 | iSales 数量优势明显 |
| CRM重复过滤 | 需要另行处理 | 自动检查 | Key Search 更适合现有CRM流程 |

需要注意：iSales 的359个邮箱是“候选邮箱值”，不是359个已经验证可送达、且确认属于当前人员的邮箱。单个人员可能同时出现多个邮箱组合、免费邮箱或其他公司域名邮箱。

因此，不能只用邮箱数量判断实际可开发价值。

## 四、三家公司实际表现

### Grinding Techniques

iSales 找到61名人员，覆盖采购、质量、生产、销售和区域管理等多个层级；Key Search 找到的人数明显较少。

Key Search 找到了 Managing Director 等核心负责人，公司公共邮箱和电话覆盖与 iSales 基本相当，并且不会把公司公共电话或公共邮箱强行归给某个人。

业务判断：Key Search 在公司入口和管理层方面表现较好，iSales 的部门人员名单更完整。

### Samancor Chrome

iSales 找到21名去重人员，主要价值在采购、库存、供应链和矿山运营岗位。Key Search 找到的人员数量与其较接近，但主要集中在公司领导、矿山负责人和冶炼厂管理层。

- iSales 更适合寻找采购执行人员和业务中层。
- Key Search 更适合确认公司领导和关键运营负责人。

业务判断：在公开资料丰富的大公司中，Key Search 更偏向公司领导和运营负责人，iSales 更偏向采购和供应链中层。

### Pace Industries

iSales 找到37名去重人员，包含 Plant Manager、Purchasing、Production 和 Quality 等大量目标岗位。Key Search 找到10名确定或待确认人员，包括 Senior Buyer、Purchasing Manager 和部分公司高管。

业务判断：对于分支机构多、员工数量大的制造企业，结构化人员库在员工覆盖数量上表现更强，公开网页搜索则更偏向官网管理层。

## 五、两套工具分别适合什么业务场景

| 使用场景 | 更适合的工具 | 原因 |
|---|---|---|
| 判断公司是否值得开发 | Key Search | 可结合公司业务、工艺和产品匹配度 |
| 获取公司公共邮箱和电话 | Key Search | 本次达到 iSales 约89%的数量覆盖 |
| 寻找老板、高管和官网负责人 | Key Search | 官网证据和当前任职判断更可靠 |
| 寻找采购、供应链和工厂中层 | iSales目前更强 | 人员数据库覆盖更广 |
| 一次获得大量员工名单 | iSales目前更强 | 候选人员数量明显更多 |
| 判断人员是否仍在目标公司 | Key Search | 会保存证据并区分确定、可能和未验证 |
| 避免重复开发CRM已有人员 | Key Search | 可按姓名、邮箱、电话和LinkedIn去重 |
| 直接批量使用个人邮箱 | 两者都需谨慎 | iSales邮箱多但不等于已验证；Key Search数量较少 |

## 六、主要能力差异

### Key Search 的突出能力

- 公司公共邮箱和总机电话发现
- 官网 Contact、Management、Leadership 等页面整理
- 老板、高管、厂长和公开技术负责人的发现
- 人员当前任职证据检查
- CRM 已有联系人去重
- 公共联系方式与个人联系方式分离

### iSales 的突出能力

- 大型企业100人以上的批量员工发现
- 采购、供应链、生产、质量等中层岗位的系统覆盖
- 大量个人邮箱组合生成
- 类似商业人员数据库的完整组织结构

## 七、数据风险对比

### iSales 的主要风险

- 同一个人可能显示多个候选邮箱。
- 可能包含个人免费邮箱、其他公司邮箱或历史邮箱。
- 找到人员不代表其目前仍在目标公司任职。
- 公共邮箱和电话会增加总联系人数量，但不等于增加了同等数量的 Key Person。

### Key Search 的主要风险

- 人员数量偏少，可能遗漏真正负责采购的中层人员。
- 公开资料较少的公司容易只有公共联系方式，没有具体人员。
- 验证要求较高，因此一些可能有价值的人会停留在“待确认”状态。

## 八、扩大样本时的对比指标

后续如扩大到30至50家公司，可继续记录：

- 每家公司最终可人工联系的目标人员数
- 采购、供应链、厂长、生产、质量和技术岗位覆盖率
- 当前任职错误率
- 错公司人员比例
- 有效 LinkedIn、邮箱和电话数量
- 每个最终可用联系人的实际成本

统一评价指标包括：

- 目标岗位人员数量及岗位分布
- 当前任职准确率达到90%以上
- 错公司人员低于3%
- 公共联系方式覆盖率
- 每个最终可用联系人的综合成本

## 九、对比总结

本次三家公司样本显示：

1. iSales 的人员数量、采购及工厂中层覆盖、邮箱候选数量更高。
2. Key Search 的官网负责人、当前任职确认、证据追溯和 CRM 去重更强。
3. 两者在公司公共邮箱和电话数量上较为接近。
4. iSales 的邮箱候选不能直接等同于已验证有效邮箱。
5. Key Search 验证标准更严格，但因此保留的人员数量更少。

综合对比：

> iSales 更像人员和邮箱候选数据库；Key Search 更像带公司判断、任职验证、证据和 CRM 去重能力的联系人研究工具。两者的优势方向不同。
